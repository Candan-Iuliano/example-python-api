# Alembic Command Reference

Run all commands from the project root using `uv run`.

## 1. Creating migrations

| Command | Purpose |
|---|---|
| `uv run alembic revision --autogenerate -m "description"` | Generate a migration based on model changes |
| `uv run alembic revision -m "description"` | Create an empty migration for manual changes |

## 2. Applying migrations

| Command | Purpose |
|---|---|
| `uv run alembic upgrade head` | Apply all pending migrations |
| `uv run alembic upgrade +1` | Apply the next migration |
| `uv run alembic upgrade <revision_id>` | Upgrade to a specific revision |

## 3. Reverting migrations

| Command | Purpose |
|---|---|
| `uv run alembic downgrade -1` | Revert the most recent migration |
| `uv run alembic downgrade <revision_id>` | Downgrade to a specific revision |
| `uv run alembic downgrade base` | Revert all migrations |

**Warning:** Downgrading can delete tables or data. Review the migration's `downgrade()` function first.

## 4. Checking migration status

| Command | Purpose |
|---|---|
| `uv run alembic current` | Show the database's current revision |
| `uv run alembic history` | Show migration history |
| `uv run alembic heads` | Show the latest revision(s) |
| `uv run alembic branches` | Show migration branches |
| `uv run alembic check` | Check whether model changes would generate a new migration |

## 5. Useful workflow

When changing SQLAlchemy models:

1. Update the model in `app/models.py`.
2. Generate a migration:
   `uv run alembic revision --autogenerate -m "describe change"`
3. Open the generated file under `migrations/versions/`.
4. Review both `upgrade()` and `downgrade()`.
5. Apply the migration:
   `uv run alembic upgrade head`
6. Verify the database schema.

## Important reminders

- **Models define the desired schema; migrations change the actual database.**
- Autogenerate is a starting point, not a guarantee. Always inspect generated migrations.
- Never delete or rewrite migrations that have already been applied to a shared or important database.
- To undo an applied change, generally create a new migration rather than rewriting migration history.
- Alembic tracks the current database revision in the `alembic_version` table.
- `upgrade head` brings the database to the latest migration.
