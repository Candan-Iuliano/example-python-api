# Python Project Setup Cheat Sheet

A quick setup reference for starting a small Python API project with `uv`, FastAPI, SQLAlchemy, PostgreSQL, Alembic, and pytest.

## 1. Create and initialize the project

Run in PowerShell:

```powershell
mkdir geospatial-api
cd geospatial-api

uv init
uv venv

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

`uv init` initializes the Python project and creates the project metadata file. `uv venv` creates the virtual environment. Activating it makes the environment's Python available in the current PowerShell session.

## 2. Install dependencies

```powershell
uv add sqlalchemy "psycopg[binary]" alembic fastapi uvicorn
uv add --dev pytest
```

What these are for:

- `sqlalchemy`: ORM and database queries.
- `psycopg[binary]`: PostgreSQL driver.
- `alembic`: database schema migrations.
- `fastapi`: REST API framework.
- `uvicorn`: ASGI server used to run FastAPI.
- `pytest`: automated tests.

For the Python 3.15 Windows environment used during practice, installing `uvicorn[standard]` caused a PyYAML build issue. Plain `uvicorn` worked, so use the simpler dependency unless you have a reason to add the extra.

## 3. Create the basic directories and package file

```powershell
mkdir app
mkdir data
mkdir tests

New-Item app/__init__.py
```

Create the other files in VS Code:

```text
app/
    __init__.py
    main.py
    database.py
    models.py
    schemas.py
    logging_config.py

data/
    # supplied JSON/CSV files

tests/
    # pytest files
```

## 4. Initialize Alembic

```powershell
uv run alembic init migrations
```

This generates:

```text
alembic.ini
migrations/
    env.py
    script.py.mako
    versions/
```

Then configure `migrations/env.py` to import your SQLAlchemy `Base` and set:

```python
target_metadata = Base.metadata
```

Make sure the models are imported in `env.py` so their tables are registered in `Base.metadata`.

## 5. Generate and apply migrations

After defining or changing SQLAlchemy models:

```powershell
uv run alembic revision --autogenerate -m "initial schema"
uv run alembic upgrade head
```

For later model changes, use a descriptive migration message, for example:

```powershell
uv run alembic revision --autogenerate -m "add analysis results"
uv run alembic upgrade head
```

Review autogenerated migration files before applying them. Autogeneration is a starting point, not a guarantee that every schema change is correct.

## 6. Useful commands while developing

```powershell
# Run tests
uv run python -m pytest -v

# Start FastAPI with automatic reload
uv run uvicorn app.main:app --reload

# Check current Alembic revision
uv run alembic current

# Show migration history
uv run alembic history

# Apply latest migrations
uv run alembic upgrade head

# Show installed project dependencies
uv tree
```

When the server is running, useful URLs are:

- `http://127.0.0.1:8000/health`
- `http://127.0.0.1:8000/docs`

## 7. What creates which files?

| Command | Main result |
|---|---|
| `uv init` | Python project metadata, including `pyproject.toml` |
| `uv venv` | `.venv/` virtual environment |
| `uv add ...` | Installs dependencies and updates `pyproject.toml` and `uv.lock` |
| `mkdir app data tests` | Creates your application directories |
| `New-Item app/__init__.py` | Marks `app` as a Python package |
| `uv run alembic init migrations` | Creates Alembic configuration and migration scaffolding |
| `uv run alembic revision --autogenerate ...` | Creates a migration script in `migrations/versions/` |
| `uv run alembic upgrade head` | Applies migrations to the database; it does not create a project file |

## 8. Target project layout

```text
geospatial-api/
│
├── app/
│   ├── __init__.py
│   ├── main.py
│   ├── database.py
│   ├── models.py
│   ├── schemas.py
│   └── logging_config.py
│
├── data/
│   └── input.json
│
├── migrations/
│   ├── env.py
│   ├── script.py.mako
│   └── versions/
│
├── tests/
│   └── test_*.py
│
├── .venv/
├── alembic.ini
├── pyproject.toml
└── uv.lock
```

The `app` modules, `data`, and `tests` are your application structure. Alembic creates its own migration scaffolding. `uv` manages the Python project, dependencies, lockfile, and virtual environment.

## Important reminders

- `uv init` does **not** build the application for you; it initializes the project.
- `uv add` installs packages and records dependencies.
- `alembic init` creates migration scaffolding.
- `alembic revision --autogenerate` creates a migration file by comparing model metadata with the database schema.
- `alembic upgrade head` applies pending migrations.
- Do not commit `.venv/` or database passwords. Use environment variables or an untracked local environment file for secrets.
